# 员工任务管理系统 — 完整需求文档

本文档合并了原始需求与已确认的补充规则，作为后续设计与实现的唯一依据。

---

## 1. 业务背景与目标

团队需要一个简单的内部工具，用于管理员工任务。

系统提供：任务的创建、查询、过滤、更新、软删除，以及按状态的数量统计。系统面向已登录的团队成员；管理员负责用户管理，并可处理全部任务。

项目建议目录名：`vibe-training`。项目落地路径待定。

---

## 2. 技术选型

| 层次 | 选型 |
|------|------|
| 后端 | FastAPI |
| 数据库 | PostgreSQL |
| 前端 | 原生 HTML / CSS / JavaScript |
| 部署 | Docker、docker-compose（后端、前端、PostgreSQL） |

### 2.1 原结构的问题

原始推荐把 `main.py`、`models.py`、`schemas.py`、`crud.py` 平铺在 `app/` 下。按本期范围（健康检查、JWT、用户、任务、统计、软删除、引导管理员），若把**全部 HTTP 接口写在 `main.py`**，该文件会同时承担：

- 创建 FastAPI 应用
- 生命周期（建表、引导首位管理员）
- 全部路由与权限判断

这不合理。`main.py` **只负责组装应用**：读取配置、挂载路由、注册异常处理与 lifespan。**接口代码放在 `routers/`。**

同时保留一层即可，不拆过细的 `core/`、`domain/`、`infrastructure/`。

### 2.3 后端文件职责

| 文件 | 写什么 | 不写什么 |
|------|--------|----------|
| `main.py` | `FastAPI()`、`include_router`、CORS、lifespan（建表/引导管理员） | 具体 path 处理函数 |
| `config.py` | 配置项 | 业务逻辑 |
| `routers/*.py` | 路由、状态码、调用 deps/crud | 直接拼 SQL、密码算法细节 |
| `crud/*.py` | 查询与持久化 | `Request` / HTTP 异常展示文案堆砌（权限 403 可在 router 或 deps） |
| `deps.py` | `get_db`、`get_current_user`、`require_admin` | 路由定义 |
| `security.py` | hash / verify / encode / decode | 数据库访问 |
| `models.py` | 表结构 | API 形状 |
| `schemas/` | 请求体、响应体、分页 | ORM 对象当响应直接返回（除非明确配置） |

前端仍为原生三件套：页面骨架在 `index.html`，样式与脚本分目录，避免单文件 `app.js` 塞进登录、列表、管理员表单全部逻辑到无法维护；也不上框架。

## 3. 角色与权限

### 3.1 角色

| 角色 | 说明 |
|------|------|
| 管理员（admin） | 管理系统用户；对全部任务拥有查看、修改、删除权限 |
| 普通成员（member） | 可查看全部未删除任务；只能修改、删除**自己负责的**任务 |

无开放注册。仅管理员可以创建用户。

### 3.2 权限矩阵

| 操作 | 未登录 | 普通成员 | 管理员 |
|------|--------|----------|--------|
| 健康检查 | 允许 | 允许 | 允许 |
| 登录 | 允许 | 允许 | 允许 |
| 查看当前用户 | 否 | 允许 | 允许 |
| 创建用户 | 否 | 否 | 允许 |
| 列出用户（供选择负责人） | 否 | 允许（至少只读名单） | 允许 |
| 创建任务 | 否 | 允许 | 允许 |
| 查看任务列表 / 详情 | 否 | 允许（默认不含已删） | 允许（默认同左；可含已删） |
| 更新任务（内容/状态/优先级等） | 否 | 仅当自己是当前负责人 | 允许 |
| 更改负责人 | 否 | 仅当自己是当前负责人 | 允许 |
| 删除任务（软删除） | 否 | 仅当自己是当前负责人 | 允许 |
| 用 `include_deleted=true` 查看已删 | 否 | 否 | 允许 |
| 统计 | 否 | 允许（不含已删） | 允许（始终不含已删） |

说明：

- 普通成员创建任务时，可以把负责人指定为**任意已存在用户**（允许给别人派活）。
- 更改 `assignee` 后，原负责人若不再是负责人且不是管理员，则失去对该任务的修改与删除权。
- 状态流转**无限制**（例如允许 `done` 改回 `todo`）。

## 4. 认证与用户

### 4.1 认证方式

- 使用 **JWT**。
- 登录成功后返回 token。
- 除健康检查、登录外，其余接口均需请求头：`Authorization: Bearer <token>`。
- 未带 token、token 无效或过期：返回 `401`。
- 已登录但权限不足：返回 `403`。

### 4.2 用户来源

- **无开放注册接口。**
- **仅管理员**可通过接口创建用户。
- 第一个管理员：应用**首次启动**时，读取环境变量（如 `ADMIN_USERNAME`、`ADMIN_PASSWORD`）引导创建**唯一**初始管理员。若库中已有管理员，则不再用环境变量重复创建。

### 4.3 用户数据（最低字段）

| 字段 | 说明 |
|------|------|
| id | 用户主键 |
| username | 登录名，唯一 |
| password_hash | 密码哈希，不明文存储 |
| role | `admin` 或 `member` |
| created_at | 创建时间 |

前端需提供：登录、当前用户展示、管理员创建用户、任务界面中选择负责人。

## 5. 任务数据模型

### 5.1 字段

| 字段 | 说明 |
|------|------|
| id | 任务主键 |
| title | 标题 |
| description | 描述 |
| assignee_id | 负责人，外键关联用户，必填 |
| status | 状态 |
| priority | 优先级 |
| created_at | 创建时间（UTC） |
| updated_at | 更新时间（UTC），创建时与 `created_at` 一致，此后每次有效更新刷新 |
| deleted_at | 软删除时间；`NULL` 表示未删除 |

对外 JSON 可同时返回负责人用户名（如 `assignee` 或 `assignee_username`），便于列表展示；过滤负责人时以**用户 id** 为准。

### 5.2 枚举

**status（仅允许）：**

```text
todo
doing
done
```

**priority（仅允许）：**

```text
low
medium
high
```

**role（仅允许）：**

```text
admin
member
```

### 5.3 字段校验

**title**

- 必填。
- 去除两端空格后不能为空。
- 最大 200 个 Unicode 字符。

**description**

- 可空。
- 最大 2000 个 Unicode 字符。

**assignee / assignee_id**

- 必填。
- 必须是已存在且有效的用户。
- 原始「最大 100 字符、去空格非空」在改为用户外键后，不再作为自由文本规则；创建/更新时传用户 id（或系统可解析的稳定用户标识）。

**status**

- 仅允许 `todo` / `doing` / `done`。
- 创建时可不传，**默认 `todo`**。
- 若传入非法值，返回 `422`（或统一校验错误 `400`，全项目保持一种即可）。

**priority**

- 仅允许 `low` / `medium` / `high`。
- **创建时必传**，无默认值。

## 6. 用户故事

### US-01 创建任务

作为已登录成员，我希望创建任务并指定负责人和优先级。

验收要点：

- 必须登录。
- 必须指定已存在用户为负责人。
- 必须指定优先级。
- 可不传状态，默认为 `todo`。
- 标题、描述符合校验规则。

### US-02 查询任务

作为已登录成员，我希望看到任务列表和单条详情。

验收要点：

- 默认不返回已软删任务。
- 列表分页、排序见第 8 节。
- 普通成员可看到全部未删除任务（含他人负责的）。

### US-03 过滤任务

作为已登录成员，我希望按 status、priority、assignee 过滤。

验收要点：

- 支持单条件与组合条件。
- 组合条件为 **AND**。
- 匹配方式为**精确匹配**。
- `assignee` 过滤使用用户 id。
- 过滤在未删除集合上进行（管理员另见 `include_deleted`）。

示例：

```text
GET /tasks?status=doing
GET /tasks?priority=high
GET /tasks?assignee=<user_id>
GET /tasks?status=todo&priority=high
```

### US-04 更新任务

作为有权限的用户，我希望修改任务内容和状态。

验收要点：

- 管理员可改任意未删除任务。
- 普通成员仅当自己是当前负责人时可改。
- 提供全量更新（PUT）与部分更新（PATCH）。
- 可修改标题、描述、状态、优先级；负责人更改规则见 3.2。
- 无状态流转限制。
- 更新成功后刷新 `updated_at`。
- 对已软删任务更新：视为不存在，返回 `404`。

### US-05 删除任务

作为有权限的用户，我希望删除错误创建的任务。

验收要点：

- **软删除**：写入 `deleted_at`，不物理删除行。
- 权限与更新相同：管理员或当前负责人。
- **无恢复接口**。
- 对已删除任务再次 DELETE：返回 `404`。
- 普通成员无法通过详情或列表看到已删任务。

### US-06 统计

作为已登录成员，我希望看到任务数量统计。

统计项：

```text
总任务
TODO 数
DOING 数
DONE 数
```

验收要点：

- **始终不含已软删任务**。
- 不受 `include_deleted` 影响。
- 统计范围为全库未删除任务（不随当前列表分页或过滤条件变化），除非后续另开「带过滤的统计」需求。

### US-07 登录与用户管理（补充）

作为用户，我需要登录后使用系统。  
作为管理员，我需要创建成员或管理员账号。

验收要点：

- JWT 登录。
- 管理员创建用户时指定用户名、密码、角色。
- 无注册页面/接口。

## 7. API 要求

### 7.1 健康检查与认证

| Method | Path | 登录 | 作用 |
|--------|------|------|------|
| GET | `/health` | 否 | 健康检查 |
| POST | `/auth/login` | 否 | 登录，返回 JWT |
| GET | `/auth/me` | 是 | 当前用户信息 |
| POST | `/users` | 是（仅管理员） | 创建用户 |
| GET | `/users` | 是 | 用户列表（选择负责人；可不返回密码哈希） |

路径前缀若统一加 `/api` 需在实现与文档中保持一致；未另约定时以上表为准。

### 7.2 任务与统计

| Method | Path | 登录 | 作用 |
|--------|------|------|------|
| GET | `/tasks` | 是 | 任务列表、过滤、分页 |
| GET | `/tasks/{id}` | 是 | 任务详情 |
| POST | `/tasks` | 是 | 创建 |
| PUT | `/tasks/{id}` | 是 | **全量**更新（可改字段均需按约定提交） |
| PATCH | `/tasks/{id}` | 是 | **部分**更新（只传要改的字段） |
| DELETE | `/tasks/{id}` | 是 | 软删除 |
| GET | `/stats` | 是 | 统计 |

### 7.3 列表查询参数

| 参数 | 说明 |
|------|------|
| status | 可选，精确匹配 |
| priority | 可选，精确匹配 |
| assignee | 可选，用户 id，精确匹配 |
| page | 页码，从 **1** 开始，默认 `1` |
| page_size | 每页条数，默认 **20**，最大 **100**，超出则按校验错误处理或截断到 100（实现时选定一种并写进 API 文档） |
| include_deleted | 仅管理员有效。`true` 时列表可包含已软删任务。普通成员传入该参数应忽略或 `403`（实现时选定一种：建议 **403**） |

列表响应需包含分页元数据，例如：`items`、`total`、`page`、`page_size`。

### 7.4 列表排序

1. 优先级：`high` > `medium` > `low`
2. 同一优先级内：`created_at` **降序**（新的在前）

### 7.5 创建任务请求要点

- 必填：`title`、`assignee`（用户 id）、`priority`
- 可选：`description`、`status`（默认 `todo`）
- `id`、`created_at`、`updated_at`、`deleted_at` 由服务端生成，客户端不可指定

### 7.6 错误与资源可见性

| 场景 | HTTP |
|------|------|
| 未认证 | 401 |
| 已认证无权限（改/删他人任务、非管理员创建用户、非管理员 include_deleted 等） | 403 |
| 任务不存在，或对当前用户不可见（含已软删对非授权查看） | 404 |
| 校验失败 | 422 或 400（全项目统一） |

对已软删任务：

- 默认 GET 详情：`404`
- 管理员带 `include_deleted` 的列表中可见；详情是否对管理员始终可见：约定为**管理员 GET `/tasks/{id}` 可以看到已删任务**（否则管理员无法点开已删记录）。普通成员 GET 已删 id 为 `404`。

---

## 8. 软删除细则

- 使用 `deleted_at` 标记，不做物理删除。
- 默认列表、默认详情（非管理员）、统计均排除已删。
- 无恢复接口。
- 管理员可通过列表参数 `include_deleted=true` 查看已删任务。
- 统计**永远**不含已删，该参数不影响 `/stats`。

---

## 9. 前端范围

原生页面至少包括：

- 登录
- 任务列表（过滤、分页、排序结果展示）
- 创建 / 编辑任务（负责人下拉来自用户列表）
- 删除确认（软删除）
- 统计数字展示
- 管理员：创建用户
- 按角色隐藏无权限操作（例如他人任务对成员不显示编辑/删除）

## 10. 默认实现约定（未再单独表决）

以下作为实现默认值，若与后续口头变更冲突，以变更后的书面记录为准。

- 时间戳时区：**UTC**
- 字符串长度：**Unicode 字符数**，非字节数
- 过滤：**精确匹配** + **AND**
- `GET /health` 不校验登录
- 密码存储哈希，不明文入库、不在 API 中回传
- JWT 过期时间在部署文档中写明（如 8 小时或 24 小时）

## 11. 非功能要求（最低）

- 内部工具，需 Docker Compose 可一键启动（PostgreSQL + 后端 + 前端）。
- 提供 `.env.example`，包含数据库连接与初始管理员环境变量说明。
- `docs/api.md` 与本文 API 一节保持一致。
- 提供 README、部署说明与基本故障排查。

---

## 12. 明确不在本期范围

- 开放注册、OAuth、SSO
- 任务恢复（从软删除恢复）
- 状态机强制流转（如必须 `todo → doing → done`）
- 评论、附件、截止日期、工时
- 按当前过滤条件变化的统计
- 审计日志、操作历史
- 多租户 / 多团队隔离

## 13. 验收清单（摘要）

- [ ] 未登录无法访问任务与统计
- [ ] 环境变量可引导创建首位管理员；之后仅管理员建用户
- [ ] 创建任务：优先级必填，状态默认 todo，负责人必须是已有用户
- [ ] 列表分页默认 20、最大 100；排序为优先级再按创建时间降序
- [ ] 过滤支持 status、priority、assignee 及组合 AND
- [ ] PUT 全量、PATCH 部分更新均可用
- [ ] 成员只能改/删自己负责的任务，但能看全部未删任务
- [ ] 管理员可改/删全部；可查看已删列表；统计不含已删
- [ ] DELETE 为软删除；重复删除或对成员隐藏的已删资源返回 404
- [ ] `/stats` 返回总数与三种状态计数，不含已删
- [ ] 无状态流转限制；负责人变更后权限立即按新负责人计算
