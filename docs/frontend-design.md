# 前端设计方案

依据《需求分析.md》第 9 节与 `docs/plan.md` 阶段 6。实现前以本文为视觉与交互依据。

---

## 对象、观众、主任务

- **对象**：团队内部工单台，用来派活、接手、改状态，不是对外产品站。
- **观众**：已登录成员；管理员额外管账号。一天会反复打开，而不是参观一次。
- **主任务**：在名单里找到一条任务，看清负责人和状态，立刻改或删。统计图区分三种数据：状态占比、优先级高低、谁手上最多，各用适合的图，点图即筛列表。

界面按「工位上的作业单」来做：左列是台账，右列是当前这一张单。不做成卡片墙，也不做成看板列。

---

## 设计原则

1. **任务是记录，不是卡片。** 列表用横线和左缘色条，不用一套圆角阴影卡片。
2. **负责人与标题同等重要。** 成员找的是「谁的活」，不是封面图。
3. **大胆只用在一处：优先级左缘。** high 用施工黄签，medium / low 用更深/更浅的墨线。状态用短词，不用一排彩色胶囊。
4. **表单不弹层。** 新建、编辑、删前确认都在右侧单据区完成；管理员「添加成员」也落在同一侧栏，不另开一套后台。
5. **文案按动作命名。** 按钮写「登录」「新建任务」「保存」「删除」「添加成员」。空列表写清下一步：还没有任务，新建一条并指定负责人。
6. **一种数据一种图。** 状态用环（看占比），优先级用柱（看高低），负责人用横条（看谁手上多）。三张图**同时出现**，读的是三组不同聚合，不是同一组数字画三遍。点哪张图，就只改列表里对应的那一个筛选项。不上四张 KPI 卡、不给每张图套卡片、不引入图表库。

## 色彩（6 个命名色）

| 名称 | Hex | 用途 |
|------|------|------|
| Paper | `#EEF2F4` | 页面底，冷灰纸，不是暖奶油 |
| Sheet | `#F7F9FA` | 主工作面（台账 + 单据） |
| Ink | `#243542` | 正文、标题 |
| Rule | `#C5D0D8` | 分隔线、输入框边 |
| Mute | `#5C6B75` | 次要说明、时间 |
| Tab | `#C9A227` | 仅 high 优先级左缘；删除按钮的危险态用更深的 `#9A3B32`，不进入主色板当装饰 |

进行中、已完成不用额外品牌色：`doing` 在列表里用 Ink 加一条短下划线式标记即可；`done` 用 Mute，标题不加删除线（删线会让人以为任务没了）。

## 字体

- **正文 / 控件**：`IBM Plex Sans` + `Noto Sans SC`（工程图纸常用的无衬线，中文用思源黑体一类的 Noto SC）。
- **产品名（仅登录页顶上一行、主界面左上角）**：`IBM Plex Serif` + `Noto Serif SC`，字号接近正文，不当海报标题。
- 字阶：页面名 22px / 列表标题 16px / 正文 14px / 辅助 12px。行宽保持在约 40–60 个汉字，右侧单据不要拉满整屏。
- 不用全大写英文标签，不用等宽字体做数据角标。

Google Fonts 引入上述四族即可；系统回退为 `Source Han Sans SC`, `serif`, `sans-serif`。

## 布局

左对齐。登录页不是居中悬浮卡片；主界面不是左侧导航 + 卡片栅格。

### 登录：整页就是一张未填写的作业单

```
+-----------------------------------------------------+
| 员工任务管理系统                                    |
| 用已有账号进入工单台。没有账号请找管理员。            |
|                                                     |
| 用户名  [                              ]            |
| 密码    [                              ]            |
| [ 登录 ]                                            |
| 用户名或密码不对。                                   |
+-----------------------------------------------------+
```

字段左对齐、标签在上。没有插画、没有左右分栏营销区。

### 主界面：台账 + 单据（master–detail）

```
+-- 顶栏（矮） ------------------------------------------+
| 员工任务管理系统                          enz  退出     |
+--------------------------------------------------------+
| 12件                                                     |
|  (环 状态)     [高][中][低] 柱     alice ████            |
|                            优先级     dave ███  负责人   |
|  待办 4              进行中 3              已完成 5      |
|  待办 4     进行中 3     已完成 5                      |
+---------------------------+----------------------------+
| 状态 [全部 v] 优先级 [ ]  | 写周报                     |
| 负责人 [全部 v]  [新建]   | 负责人 dave  进行中  高     |
| ---------------------------| 描述 ……                   |
| █ 写周报     进行  dave   | [保存]  [删除]             |
| │ 修登录     待办  alice  |                            |
| │ 整理文档   完成  enz    |  或空态：选左侧一条，       |
|                           |  或点「新建任务」。         |
+---------------------------+----------------------------+
```

- 统计占顶栏和台账之间的图区，**三张图并排同时出现**，分别读状态、优先级、负责人，不是切换、也不是三张独立卡片。数据来自扩展后的 `GET /api/stats`，全库未删除任务，**不随当前列表筛选变化**。左上角总件数通管全区。
- 左列是筛选 + 分页 + 列表。当前行用 Sheet 上更深一点的底，而不是描边卡片。
- 左缘 `█` 只给 high；medium 用半高短杠；low 只用 Rule 色细线。
- 成员看别人的任务：右侧只读，没有保存/删除。自己的和高权限管理员才出现这两个按钮。
- 「添加成员」仅管理员可见，放在顶栏用户名左侧；点开后右侧变成用户表单，列表保持。
- 删除：右侧先变成确认文案「将删除这条任务，列表里不再显示。」主按钮改成「确认删除」，没有浏览器 `confirm()`。

### 窄屏（< 800px）

先列表；点一条或「新建」后，单据盖住全宽，顶上提供「返回列表」。统计图区改为纵向排列：环 → 柱 → 横条，不改成数字卡。

## 对照简报后的修正

初稿容易滑向「四张统计卡 + 圆角任务卡 + 中间登录盒」。已改掉：

| 丢掉的默认 | 换成 |
|------------|------|
| 奶油底 + 衬线海报 + 陶土强调 | 冷灰纸 + 钢青墨 + 黄签只表示 high |
| 大数字 KPI 卡 / 三图同画一组数 | 状态环、优先级柱、负责人横条同时出现，各管各的筛选 |
| 每条任务一张卡片 | 台账行 + 左缘优先级 |
| 新建/编辑用弹窗 | 右侧单据 |
| 居中登录卡 | 整页作业单 |

动效：不做入场 cascade。列表换行、打开确认删除时，右侧内容瞬间替换，必要时 120ms 透明度。三张图在数据刷新时各自用不超过 200ms 过渡弧长/柱高/条宽；`prefers-reduced-motion` 时不过渡。

## 统计图：三种数据，三种图

列表分页最多 100 条，前端没法自己加总全库，所以统计必须走接口。现有 `GET /api/stats` 只有状态四项，不够画出另外两张图。实现前端时**扩展同一接口**（仍排除已软删、仍不受列表筛选影响），不另开「带过滤的统计」——那是需求文档明确不做的。

建议响应：

```json
{
  "total": 12,
  "todo": 4,
  "doing": 3,
  "done": 5,
  "priority": { "high": 2, "medium": 5, "low": 5 },
  "assignees": [
    { "user_id": 1, "username": "alice", "count": 4 },
    { "user_id": 2, "username": "dave", "count": 3 }
  ]
}
```

`assignees` 只含未删除任务数 > 0 的人，按件数降序。超过 8 人时图上画前 7 名，第 8 档合并为「其余」，「其余」不可点（没有对应的单一 `assignee` 筛选）。

原生 SVG，不引入图表库。三张图并排，不套卡片。左上角「12件」是全区总任务。

宽屏（≥ 800px）横排，大致 3 : 3 : 4（负责人横条稍宽，因为有姓名）。每张图上方 12px Mute 标题说明数据，不是装饰 eyebrow：`状态` `优先级` `负责人`。窄屏自上而下：环、柱、横条。

### 哪张图读哪组数

| 图 | 数据 | 为什么用这种图 | 点击后改哪个筛选 |
|----|------|----------------|------------------|
| **环** | todo / doing / done | 三部分合成 100%，看占比 | `status` |
| **柱** | high / medium / low | 有固定顺序的三项比较高低；high 柱用 Tab 黄，与列表左缘一致 | `priority` |
| **横条** | 各负责人未删任务数 | 像花名册，看谁手上多 | `assignee`（用户 id） |

环的三段色仍用钢青灰，不占用黄签：

| 状态 | 填充 |
|------|------|
| 待办 | `#7A8B96` |
| 进行中 | `#243542` |
| 已完成 | `#C5D0D8` |

优先级柱：high = Tab `#C9A227`，medium = Ink，low = Rule。柱下标注「高 / 中 / 低」和件数。

负责人横条：单色 Ink 填长度，左侧姓名，右侧件数。没有任务的人不出现。

每张图自己带可点图例（环：待办/进行中/已完成；柱：高/中/低；横条：姓名即图例）。不把三组图例混成一排。

### 交互

三张图**独立选中**，和左侧三个筛选项一一对应，组合仍是 AND。

| 操作 | 结果 |
|------|------|
| 悬停环的一段 / 一根柱 / 一条横条 | 只强调这一张图里的该项；提示如 `进行中 3件，占 25%` 或 `alice 4件`。 |
| 单击环的一段 | 「状态」筛成该值；再点同一段则回到全部。柱和横条的选中不变。 |
| 单击一根优先级柱 | 「优先级」筛成该值；再点取消。 |
| 单击一条负责人横条 | 「负责人」筛成该用户；再点取消。 |
| 在左侧下拉里改状态/优先级/负责人 | 对应那一张图的选中跟着变，另外两张不动。 |
| 点图之后 | 只动被点的那个筛选；分页回到第 1 页。 |
| 总数为 0 | 三张图都画空轨/空环，提示「还没有任务」，不可点。 |
| 某一档为 0 | 环上不画该弧；柱高为 0 仍留柱位但禁用；横条不出现该人。 |
| 键盘 | 每张图的图例 `button` 为键盘主路径，图形本身也可聚焦。 |

图上数字始终是全库未删除统计。筛完后列表可能变短，三张图比例都不变：图回答「整体怎样」，列表回答「我现在看哪一刀」。

不在图上展示已删除任务（管理员「含已删除」只影响列表）。

## 页面与接口对应

| 界面 | 接口 |
|------|------|
| 登录 | `POST /api/auth/login` |
| 顶栏身份 | `GET /api/auth/me` |
| 统计图（状态环 + 优先级柱 + 负责人横条） | 扩展后的 `GET /api/stats`；点击分别带 `status` / `priority` / `assignee` 调 `GET /api/tasks` |
| 列表 / 筛选 / 分页 | `GET /api/tasks` |
| 右侧查看 | `GET /api/tasks/{id}` |
| 新建 / 保存 | `POST` / `PATCH`（编辑走 PATCH，避免 PUT 清空未展示字段） |
| 删除 | `DELETE /api/tasks/{id}` |
| 负责人下拉、添加成员 | `GET/POST /api/users` |

管理员可看已删：筛选里多一项「含已删除」，仅管理员渲染；成员不出现该控件（避免点了得到 403）。
